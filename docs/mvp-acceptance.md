# Приёмка MVP Modulyn

Дата: 2026-11-17. Ветка `codex/phase-1`. Источник статусов и подробных отчётов по каждому подшагу — [SPEC.md](../SPEC.md).
MVP принят, когда вы прошли чек-лист из раздела 4 и подтвердили. Ничего не опубликовано в интернете.

## 1. Что сделано

| Фаза | Результат |
|---|---|
| 1. Каркас | Монорепозиторий: NestJS API, Next.js, PostgreSQL, Docker Compose, проверки, документация запуска |
| 2. Изоляция компаний | Компания по поддомену; RLS в PostgreSQL на всех таблицах компаний; API работает под ролью без обхода RLS |
| 3. Вход | Один аккаунт для нескольких компаний; пароль и Google; выбор и переключение компании; сессии с ротацией и отзывом; роли; CSRF; ограничение попыток |
| 4. Платформа | Администратор платформы (только командой на сервере, обязательный второй фактор); создание, отключение компаний; платформа не видит людей и заявок |
| 5. Сотрудники | Приглашения по email, роли, отключение доступа, восстановление пароля |
| 6. Модули | Включение «Заявок» для компании платформой; отключённый модуль закрыт в API и пропадает из меню |
| 7. Заявки | Список с фильтрами, поиском и страницами; карточка; статусы с историей; назначение; ручные заявки; защита от одновременных изменений |
| 8. Заявки с сайтов | Точка приёма для сайта на любой технологии (с сервера — секрет; из браузера — список сайтов); защита от дублей и спама; журнал без данных форм; инструкция подключения; запрос сайта Nova принимается без изменения его кода |
| 9. Завершение | Сквозной тест всего пути; матрица защиты всех маршрутов; резервная копия и проверка восстановления; сроки хранения с автоочисткой; удаление заявки по запросу; понятные сообщения при сбоях; документация эксплуатации и план развёртывания |

## 3. Известные ограничения

- **Не развёрнуто в интернете** — нет HTTPS, домена, боевой почты; план — [deployment-plan.md](deployment-plan.md).
- Сайт Nova к CRM не подключён — после развёртывания, двумя настройками на сервере сайта.
- Вход через настоящий Google не проверен (нужен OAuth-клиент; автотесты используют поддельного провайдера).
- Нет редактирования заявок, комментариев, задач, уведомлений, импорта/экспорта.
- Нет удаления компаний, аккаунтов и точек приёма (только отключение).
- Для форм «из браузера» нет CAPTCHA (ловушка для ботов и лимиты).
- Полная CSP для скриптов страниц — после MVP (сейчас — запрет встраивания).
- Сроки хранения — предложение для MVP; для реальных данных подтверждает компания.
- Интерфейс только на русском.

## 4. Чек-лист для вашей приёмки (≈ 20 минут, локально)

Подготовка: Docker Desktop запущен; в корне проекта `pnpm stack:up`, затем `pnpm db:seed`. Пароль синтетических пользователей — `SEED_PASSWORD` в `apps/api/scripts/seed.mjs`. Письма — http://localhost:8025.

| # | Действие | Ожидание |
|---|---|---|
| 1 | http://app.localhost:8080 → войти как `manager@shared.example` | Список из двух компаний: Nova и Company B |
| 2 | Открыть Nova → «Заявки» | Заявки только Nova; фильтры и поиск работают |
| 3 | Сменить компанию → Company B | Другие заявки; заявок Nova не видно |
| 4 | Выйти; войти как `admin@nova.example` → Nova | В меню есть «Приём заявок» и «Пользователи» |
| 5 | «Пользователи» → пригласить `test@nova-team.example` менеджером | Письмо в Mailpit со ссылкой |
| 6 | Открыть ссылку из письма в **приватном окне** → задать имя и пароль | Вход в Nova как менеджер; пунктов «Приём заявок» и «Пользователи» нет |
| 7 | Обычное окно (администратор) → «Приём заявок» → «Новая точка приёма», «С сервера сайта» | Секрет показан один раз в жёлтом блоке; в списке — только начало секрета |
| 8 | Выполнить в терминале `pnpm smoke` | PASS; в журнале «Приём заявок» — «Дубль» (повтор заявки Smoke Website) |
| 9 | «Заявки» → «Smoke Website» | Источник «Сайт · trial», «Программа: …» в сообщении |
| 10 | Сменить статус на «В работе», назначить менеджера | История: кто и когда; в приватном окне у менеджера заявка в «Мои» |
| 11 | «Новая заявка» → имя и телефон → сохранить → «Удалить заявку» → подтвердить | Переход к списку, «Заявка удалена.» |
| 12 | Открыть в браузере `http://nova.localhost:8080/leads/<id удалённой>` | «Заявка не найдена» |
| 13 | В приватном окне (менеджер) открыть `/forms` | «Раздел доступен только администратору компании» |
| 14 | Сузить окно браузера до ширины телефона | Заявки — карточками, без горизонтальной прокрутки |
| 15 | `pnpm db:backup`, затем `pnpm db:restore-check backups/<файл>.dump` | `OK — … counts match the copy summary` |
| 16 | `pnpm db:cleanup` | Числа удалённых записей (на свежей базе — нули) |
| 17 | (по желанию) Платформа: `pnpm platform:admin create --email <ваш email> --name "<имя>"` → http://admin.localhost:8080 | Смена временного пароля, второй фактор (QR-код), список компаний без заявок и людей |

Если что-то не совпало — сообщите номер шага и что увидели.

## 5. После MVP (решение за вами)

1. Развёртывание по [deployment-plan.md](deployment-plan.md) и подключение сайта Nova.
2. Возврат на исходную страницу после повторного входа (сейчас после истечения сеанса пользователь попадает на главную компании, а не на страницу, где был).
3. Полная CSP со nonce для скриптов страниц.
4. Уведомления сотрудникам о новой заявке с сайта.
5. Редактирование заявки, комментарии, задачи.
6. CAPTCHA для форм «из браузера», если появится спам.
7. Удаление компаний и аккаунтов (с политикой хранения).
8. Обновление линтера (`typescript-eslint`) из-за уязвимости в инструменте разработки.
