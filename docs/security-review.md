## 2. Обзор по разделам ASVS (уровень 1)

| Раздел | Состояние |
|---|---|
| V2 Аутентификация | Argon2id; пароли 12–128 символов без «спецсимволов»; одинаковый ответ и время для несуществующего email; лимиты попыток по IP и аккаунту (PostgreSQL); второй фактор обязателен для платформы, секреты зашифрованы; временные пароли с принудительной сменой. Проверки утёкших паролей (HIBP) нет — сознательно (A8) |
| V3 Сессии | Cookies `HttpOnly`, `SameSite`, без `Domain`, с https — `__Host-` и `Secure`; refresh меняется при каждом обновлении, повтор старого — отзыв цепочки; простой 7 дней / абсолютно 30 (платформа 2 ч / 12 ч); выход, отключение доступа и смена пароля действуют сразу (сессия проверяется в БД на каждом запросе) |
| V4 Доступ | Глобальный guard: всё закрыто, пока не помечено `@Public`; роль из БД, не из токена; RLS в PostgreSQL как второй уровень; чужие объекты — одинаковый 404; матрица маршрутов |
| V5 Ввод | Проверка на сервере каждого поля; только JSON (кроме формы перехода с проверкой state); лимиты размера (1 МБ прокси, 32 КБ приём заявок); параметры SQL — через Prisma и параметризованные запросы |
| V7 Логи | Только коды ошибок и числа; нет паролей, токенов, email из заявок и содержимого форм; журналы аудита — без персональных данных (удаление заявки — только id) |
| V8 Данные | Секреты точек приёма и токены — только хеши; содержимое форм не хранится вне заявки; сроки хранения и удаление по запросу (9.5) |
| V9 Передача | **HTTPS ещё нет** — локальный стенд; обязательно при развёртывании (deployment-plan.md, раздел 2) |
| V13 API | CORS только для точек приёма «из браузера» и только для их сайтов; проверка Origin для всех изменяющих запросов |
| V14 Конфигурация | Секреты в `.env` (не в git и не в образах); helmet на API; `server_tokens off` в nginx; база слушает только `127.0.0.1` |

## 3. Найдено и исправлено в Phase 9

1. **Страницы интерфейса можно было встроить в чужой сайт** (clickjacking). API отдавал `X-Frame-Options`, страницы Next.js — нет. Исправлено: `apps/web/next.config.ts` — `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`; проверка в `pnpm smoke`.
2. **Право на удаление истории статусов** — при проектировании F6 первая версия миграции давала приложению `DELETE` на историю; старый тест неизменности истории это поймал. Исправлено: история удаляется только каскадом вместе с заявкой, прямого `DELETE` у приложения нет.
