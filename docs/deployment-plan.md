# План развёртывания Modulyn в интернете

Статус: **план, ничего не выполнено** (Phase 9, решение F9). Развёртывание — отдельное согласование после приёмки MVP. До него CRM работает только локально, а сайт Nova к ней не подключён.

## 1. Решения, которые нужны от вас

| # | Вопрос | Предложение по умолчанию |
|---|---|---|
| R1 | Домен CRM | Отдельный домен (например, `<имя>.app`); компании — поддомены `nova.<домен>`, вход — `app.<домен>`, платформа — `admin.<домен>` |
| R2 | Где размещать | Один виртуальный сервер **в ЕС** (данные клиентов из Германии), 2 vCPU, 4 ГБ RAM, 40+ ГБ диска; Docker Compose, как локально |
| R3 | Почтовый сервис | Сервис рассылки транзакционных писем с серверами в ЕС и SMTP-доступом |
| R4 | Где хранить резервные копии | Объектное хранилище в ЕС у **другого** провайдера или в другом регионе, копии зашифрованы |
| R5 | Юридическое | Договор обработки данных (AVV/DPA) между вами (Modulyn) и Nova; упоминание CRM в политике конфиденциальности сайта Nova — с юристом |

## 2. Что нужно доделать в проекте перед запуском

1. **HTTPS.** Сертификат на `*.<домен>` и `<домен>` (wildcard). Let's Encrypt выдаёт wildcard только через проверку DNS (DNS-01) — нужен DNS-провайдер с API. В nginx: порт 443, переадресация с 80, HSTS. В `.env`: `PUBLIC_SCHEME=https`, `PUBLIC_PORT=443`, `APP_BASE_DOMAIN=<домен>` — cookies автоматически станут `Secure` и `__Host-`.
2. **Файл Compose для сервера** (`docker-compose.prod.yml`): без Mailpit; порты 80/443 у proxy; том для сертификатов; ограничение размера логов Docker; `restart: unless-stopped`.
3. **Почта:** `COMPOSE_SMTP_URL`, `MAIL_FROM="Modulyn <no-reply@<домен>>"`; у домена отправителя — записи SPF, DKIM, DMARC. Проверка: приглашение доходит во «Входящие», а не в спам.
4. **Вход через Google (если нужен):** OAuth-клиент, redirect URI `https://app.<домен>/api/auth/google/callback`; проверка настоящим аккаунтом (автотесты используют поддельного провайдера).
5. **Образ API:** сейчас содержит инструменты сборки и Prisma CLI (нужен сервису `migrate`) — разделить образы, чтобы в работающем API не было лишнего.
6. **Seed не запускать:** `pnpm db:seed` создаёт синтетические компании и отказывается работать при `NODE_ENV=production`.

## 3. Сервер

- Вход по SSH только по ключу, без пароля и без root; брандмауэр — открыты только 22, 80, 443. База наружу не открыта (порт привязан к `127.0.0.1`).
- Автоматические обновления безопасности ОС; Docker из официального репозитория.
- `.env` создаётся на сервере (`pnpm env:init`), права `600`. `PLATFORM_TOTP_KEY` дополнительно — в менеджере паролей.

## 4. Резервные копии

- Каждую ночь: `pnpm db:backup` по расписанию (cron), затем шифрование файла и выгрузка в хранилище R4; на сервере — только последние 3 копии.
- Хранение: 7 ежедневных, 4 еженедельных, 6 ежемесячных. Старые копии удаляются — это тоже часть сроков хранения (удалённая заявка исчезает из копий по мере их ротации).
- Раз в месяц: `pnpm db:restore-check` на свежей копии; результат — в журнал эксплуатации.
- Ключи (`PLATFORM_TOTP_KEY`, `.env`) — отдельно от копий.

## 5. Наблюдение

- Внешняя проверка `https://app.<домен>/api/health/ready` раз в минуту с оповещением на почту/телефон.
- Оповещение о заполнении диска > 80 %.
- Логи: `docker compose logs api` (без персональных данных); ротация логов Docker.

## 6. Порядок запуска

1. Сервер, DNS (`<домен>` и `*.<домен>` → IP сервера), сертификат.
2. `git clone`, `pnpm install --frozen-lockfile`, `pnpm env:init`, заполнить домен и почту в `.env`.
3. `docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d --wait`.
4. `pnpm platform:admin create --email <ваш email> --name "<имя>"` → вход на `admin.<домен>`, смена пароля, второй фактор.
5. «Компании» → «Новая компания»: Nova (`nova`), первый администратор — приглашение по email.
6. Администратор Nova → «Приём заявок» → «Новая точка приёма»: «С сервера сайта», тип `trial`, доп. поле `program = Программа`.
7. На сервере сайта Nova (Strato) в `api/config.php`: `CRM_INGEST_URL` и `CRM_INGESTION_SECRET` — [integrations/web-forms.md](integrations/web-forms.md), раздел 4.
8. Пробная заявка с сайта → появилась в «Заявках», журнал — «Принята»; письма сайта приходят как раньше.
9. Первая ночная копия и `pnpm db:restore-check` по ней.

## 7. Откат

- Версия приложения: `git checkout <предыдущий тег>`, `docker compose up --build -d --wait`. Миграции только добавляют — старая версия работает с новой схемой, пока миграция не удаляет данные (такие миграции — только с отдельным планом).
- Данные: восстановление из копии — [operations.md](operations.md), раздел 3.
- Сайт Nova: очистить `CRM_INGEST_URL` — сайт продолжит принимать заявки и слать письма без CRM.
