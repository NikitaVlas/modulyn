# Phase 6 — Module Management: план и решения

Источник требований, одобрений и статусов: [SPEC](../SPEC.md). Модель: [phase2_design.md](phase2_design.md) (Module, TenantModule); платформа: [phase4_design.md](phase4_design.md).
Статус документа: **редакция 1, согласована (2026-11-16)**. Решения M1–M8 и Phase 6 одобрены сообщением «Согласен, начинай». Реализация — раздел 8 и отчёт в SPEC.

## 1. Цель и границы

Цель: у каждой компании свой набор разделов CRM. Администратор платформы включает и отключает модули для конкретной компании; отключённый модуль исчезает из меню **и** закрыт на сервере — прямой запрос к его API отклоняется. Данные модуля при отключении сохраняются.

Входит (подшаги SPEC 6.1–6.5):

- Статический реестр модулей в коде и каталог в БД, сверка между ними (6.1).
- Включение и отключение модулей компании на `admin.<домен>`, аудит (6.2).
- Серверная защита маршрутов модуля (6.3).
- Меню CRM по включённым модулям и роли (6.4).
- Тесты отключения, повторного включения и изоляции (6.5).

Не входит: сами разделы модулей (список и карточки заявок — Phase 7, приём заявок с сайта — Phase 8), динамическая загрузка кода и конструктор модулей (исключены ТЗ), настройки модуля внутри компании, тарифы и оплата.

## 2. Как это будет работать

1. В коде есть реестр модулей. Сейчас в нём один — «Заявки» (`leads`); следующий модуль разработчик добавляет в общую кодовую базу и в реестр.
2. Администратор платформы в карточке компании видит список модулей с переключателями: «Заявки — включено».
3. Отключение: пункт «Заявки» пропадает из меню CRM компании, а любой запрос к API заявок этой компании получает отказ. Заявки при этом не удаляются.
4. Повторное включение возвращает раздел со всеми данными.
5. Пользователи компании модули не включают — только видят разделы, которые им включили.

## 3. Решения для согласования

| ID | Вопрос | Предложение | Альтернативы |
| --- | --- | --- | --- |
| M1 | Где живёт список модулей | **Реестр в коде** (ключ, название, описание) — источник истины. Каталог `modules` в БД заполняется миграцией. При старте API сверяет реестр с каталогом: модуль из реестра, которого нет в БД, считается отключённым и пишется ошибка в лог; лишние записи в БД игнорируются | Каталог только в БД — можно «включить» модуль, кода которого нет |
| M2 | Кто включает модули | **Только администратор платформы**, для каждой компании отдельно, в карточке компании (как в ТЗ). Администратор компании модули не включает и не отключает | Администратор компании включает сам из доступного набора — понадобится, если появятся платные модули |
| M3 | Модули новой компании | **«Заявки» включены сразу** при создании компании — без них CRM пока пуста. Новые модули в будущем по умолчанию выключены для всех существующих компаний | Все модули выключены, пока платформа не включит |
| M4 | Ответ на запрос к отключённому модулю | **403 с кодом `MODULE_DISABLED`** и понятным сообщением. Интерфейс по этому коду показывает «Раздел отключён». Сам факт существования модуля не секрет — это функция продукта | 404, как будто маршрута нет — интерфейсу сложнее отличить от ошибки |
| M5 | Данные отключённого модуля | Сохраняются без изменений; включение возвращает их как было. Фоновые и внешние входы модуля тоже закрыты: например, в Phase 8 заявки с сайта для компании с отключёнными «Заявками» будут отклоняться | Удалять данные при отключении — необратимо |
| M6 | Как сервер защищает модуль | Декоратор `@RequireModule('leads')` на контроллере модуля; глобальный guard после проверки входа проверяет `tenant_modules` компании (в её транзакции, под RLS). Нет декоратора на маршруте компании — маршрут считается «ядром» (вход, пользователи), он всегда доступен | Проверка в каждом сервисе — легко забыть |
| M7 | Как интерфейс узнаёт меню | `GET /api/tenant/capabilities` → включённые модули и роль. Меню строится по нему; при отказе `MODULE_DISABLED` раздел показывает сообщение. Скрытие в меню — удобство, защита — только на сервере | Модули в ответе `/api/auth/me` — смешивает вход и функции |
| M8 | Чем проверить защиту, пока раздела «Заявки» ещё нет | Первый маршрут модуля — **сводка заявок по статусам** (`GET /api/leads/summary`: сколько NEW, IN_PROGRESS и т.д.) на главной странице CRM. Это реальная часть будущего раздела (по A2 её видят и менеджер, и администратор), на ней проверяется защита модуля; список, карточка и действия — Phase 7 | Тестовый маршрут только для проверок — код, который не нужен продукту |

## 4. Изменения схемы

Новых таблиц нет: `modules` и `tenant_modules` созданы в Phase 2.

- Миграция Phase 6: каталог модулей из реестра (`leads`, «Заявки»), `INSERT … ON CONFLICT DO NOTHING`; для всех существующих компаний — запись `tenant_modules` с `enabled = true` для `leads`, если её нет (сейчас seed уже включает «Заявки» для nova и company-b).
- Права runtime-роли не меняются: `tenant_modules` — SELECT/INSERT/UPDATE уже есть, изменение выполняется в транзакции целевой компании (RLS).

## 5. Подшаги и проверки

| ID | Что делаем | Проверки |
| --- | --- | --- |
| 6.1 | Реестр модулей в коде, каталог миграцией, сверка при старте | Ключи реестра и БД совпадают; модуль из реестра без записи в БД считается выключенным, в логе ошибка; неизвестный ключ не включается |
| 6.2 | Включение и отключение на платформе, модули новой компании (M3), аудит | Изменение затрагивает только выбранную компанию; новая компания получает «Заявки»; неизвестный ключ — 400; изменения в аудите платформы и компании |
| 6.3 | `@RequireModule`, guard, сводка заявок (M8) | Отключённый модуль — 403 `MODULE_DISABLED` для любой роли; включённый — сводка только своей компании; без входа — 401; «ядро» (вход, пользователи) работает при любых модулях |
| 6.4 | Возможности компании и меню | Меню показывает только включённые модули; главная показывает сводку, если «Заявки» включены; отключённый раздел — понятное сообщение |
| 6.5 | Отключение и повторное включение целиком | Доступ закрывается сразу, данные сохраняются, после включения те же данные; конфигурация другой компании не меняется; все тесты Phase 1–5 проходят |

## 6. Критерии готовности Phase 6

1. Решения M1–M8 согласованы и записаны в SPEC.
2. Платформа включает и отключает модули отдельно для каждой компании; всё в аудите.
3. Отключённый модуль недоступен через API и скрыт в меню; данные сохраняются и возвращаются при включении.
4. `pnpm check`, `pnpm test:integration`, `pnpm smoke` проходят; сценарий проверен в браузере; результаты в SPEC.

## 7. Риски

- **Забытый декоратор.** Новый маршрут модуля без `@RequireModule` окажется доступен при отключённом модуле. Смягчение: все маршруты модуля — в одном контроллере с декоратором на классе; тест проверяет, что каждый маршрут контроллера модуля отвечает `MODULE_DISABLED` при отключении.
- **Проверка модуля на каждом запросе** — ещё один короткий запрос в транзакции компании; при росте нагрузки можно объединить с проверкой сессии.

## 8. Реализация (P6-001, 2026-11-16)

Отличия от плана и решения внутри одобренной фазы:

- **Реестр:** `apps/api/src/modules/registry.ts` (`MODULES`, `ModuleKey`, `isModuleKey`). Модуль считается включённым только при наличии в реестре, в каталоге БД и включённой записи `tenant_modules` — поэтому модуль из реестра без строки каталога автоматически выключен; сверка при старте (`ModulesCatalogCheck`) только пишет ошибку в лог и не мешает запуску.
- **Миграция `20261116180000_phase6_modules`** — только данные: каталог «Заявки» (название и описание приводятся к реестру) и включение «Заявок» существующим компаниям. Запись в `tenant_modules` идёт в цикле с контекстом каждой компании: FORCE RLS действует и на владельца схемы.
- **Guard:** проверка модуля — шаг 7, после входа, ограничений и ролей (без входа — 401, а не `MODULE_DISABLED`). Маршрут без `@RequireModule` — «ядро».
- **Сводка заявок** `GET /api/leads/summary` — `groupBy` по статусу в транзакции компании (RLS), без фильтра по tenant_id в коде.
- **Платформа:** `GET /api/platform/tenants/:id/modules`, `PATCH /api/platform/tenants/:id/modules/:key` `{ enabled }`; повторная установка того же состояния ничего не меняет и не пишет аудит; аудит в журналах платформы и компании (`module.enabled/disabled`, только ключ модуля).
- **Интерфейс:** пункт меню «Заявки» и сводка на главной — по `/api/tenant/capabilities`; страница `/leads` показывает «Раздел отключён», если сервер ответил `MODULE_DISABLED`; в карточке компании на платформе — переключатели модулей с подтверждением отключения.
